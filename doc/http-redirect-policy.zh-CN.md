# HTTP 重定向策略

`max-http-redirect` 将每条 HTTP 重定向链限制为 0–20 次，默认值保持为 20。
设为 0 时，引擎会在请求重定向目标之前终止任务，返回错误码 23。该限制适用于
带 Location 响应头的 HTTP 300、301、302、303、307 和 308 响应。
设为 0 时也不接收 HTTP Link 响应头提供的镜像地址，避免通过镜像绕过重定向
限制，或在响应失败后切换到其他资源。

可通过命令行或 `aria2.addUri` 为单个下载设置此选项，也可使用
`aria2.changeOption`、`aria2.getOption`、全局配置及会话保存和恢复功能。

依赖此限制的客户端必须先检查运行中的引擎：`aria2.getVersion` 返回的功能列表
应包含 `HttpRedirectPolicyV1`。旧引擎可能静默忽略不认识的 RPC 选项。
不同重定向目标可以合法地使用相同的强 ETag，因此，复用已验证本地内容的下载
应将此选项固定为 0，避免将本地进度绑定到其他资源。
